# NEON RUSH: SWITCH

Второй этап: портретная аркада на Phaser, TypeScript и Vite. Perfect Switch, комбо, Overdrive, три семейства препятствий, кристаллы, процедурные звуки и безопасное интерактивное обучение. Сохранены две полосы, непрерывные столкновения, постепенный рост скорости и локальный рекорд. Интерфейс на русском с переключением на английский.

## Локальный запуск

Основная версия — Node.js `24.21.0` LTS из `.nvmrc`; локальный Node.js 26 также поддерживается. Версии npm-зависимостей закреплены точно, `package-lock.json` включён в исходники. Используется стабильный [Phaser 4.2.1](https://github.com/phaserjs/phaser/releases/tag/v4.2.1), TypeScript 6.0.3, Vite 8.3.4 и Vitest 5.0.3. Node.js 24 имеет статус [LTS](https://nodejs.org/en/about/previous-releases).

```bash
npm ci
npm run dev
```

Откройте http://localhost:5173/. Сервер использует фиксированный порт: если он занят, освободите его либо запустите `npm run dev -- --port 5174` и откройте http://localhost:5174/. Для браузерных тестов нужен порт 5173.

Vite также показывает сетевой адрес компьютера: его можно открыть на телефоне в той же сети при разрешённом доступе к порту 5173. GitHub Pages для локального тестирования не требуется.

## Управление

- Нажмите «Начать забег».
- Касание или щелчок по трассе меняет полосу. На клавиатуре: `Space`, `ArrowLeft` или `ArrowRight`. Каждое нажатие переключает полосу; удержание клавиши не повторяет переключение.
- Избегайте розовых преград. Смена полосы занимает 0,12 секунды; повторные касания до завершения перехода игнорируются. Столкновения проверяются по круглой сфере, включая движение между кадрами; свечение не входит в область столкновения.
- Смените полосу незадолго до опасности: GOOD даёт 50, PERFECT — 100, ULTRA PERFECT — 175 базовых очков. Бонус подтверждается после безопасного прохода преграды, а не сразу при нажатии.
- Каждый подтверждённый бонус увеличивает комбо. На 3, 6 и 10 переходах множитель становится ×1,5, ×2 и ×3. Безопасный проход без переключения не обрывает комбо.
- Точные переключения дают 10/20/30 заряда. При 100 автоматически включается Overdrive на 6 секунд: множитель бонусов удваивается, максимум ×6. Скорость и управление не меняются.
- Светлые ромбы — кристаллы: 40 базовых очков, без постоянной валюты. Проход преграды даёт 25. Эти бонусы умножаются при начислении; дистанция (1 очко за 23 единицы) не умножается.
- «Обучение» в меню проводит через шесть коротких упражнений. Дождитесь подсказки, коснитесь трассы и нажмите «Дальше». Тренировочный счёт не сохраняется; «Пропустить» запускает обычный забег.
- Звук и уменьшение эффектов переключаются в меню и на паузе. Звук запускается только после действия пользователя. При паузе и потере фокуса голоса останавливаются. Настройки действуют до перезагрузки; уменьшение движения по умолчанию учитывает `prefers-reduced-motion`.
- Кнопка `Ⅱ`, `P` или `Escape` ставит игру на паузу. `P` / `Escape` также снимают паузу.
- При уходе со страницы или потере фокуса игра останавливается. Продолжение вручную.
- После столкновения нажмите «Ещё раз» или `Enter`: перезапуск сразу сбрасывает трассу, скорость и счёт.
- Рекорд сохраняется по завершении забега в `localStorage`. Если хранилище заблокировано, игра работает и держит рекорд в памяти до закрытия страницы.

## Команды и проверки

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Сервер разработки, http://localhost:5173/ |
| `npm run typecheck` | Строгая проверка TypeScript, включая тесты и конфигурации |
| `npm run lint` | ESLint |
| `npm run test` | Модульные тесты Vitest |
| `npm run test:browser` | Проверки в Chromium через Playwright |
| `npm run build` | Проверка типов и обе отдельные сборки |
| `npm run build:preview` | Standalone в `dist/preview/` |
| `npm run build:yandex` | Основа Yandex-сборки в `dist/yandex/` |
| `npm run preview` | Просмотр standalone, http://localhost:4173/ |
| `npm run preview:yandex` | Просмотр Yandex-основы, http://localhost:4174/ |
| `npm run validate:build` | Имена файлов, ресурсы, цели сборок, размер и отсутствие внешних HTML/CSS-ресурсов |
| `npm run package:yandex` | Сборка, упаковка и проверка `artifacts/neon-rush-yandex.zip` |
| `npm run validate:zip` | Сравнение архива с текущей проверенной Yandex-сборкой |

Для тех же браузерных сценариев на готовой сборке выполните `npm run build`, затем `npm run test:browser -- --config playwright.preview.config.ts`. Этот режим самостоятельно запускает `npm run preview`.

Браузерные тесты автоматически запускают Vite или используют уже запущенный сервер. На Arch Linux используется установленный `/usr/bin/chromium`. На другой системе установите браузер командой `npx playwright install chromium` или задайте `CHROMIUM_PATH=/absolute/path/to/chromium npm run test:browser`.

Модульные тесты проверяют границы точности, безопасное подтверждение и отмену награды, спам ввода, все ступени комбо, расчёт очков, Overdrive и паузу, кристаллы, обучение, ограничения аудио, перезапуск, состояния перехода, паузу, круглые и непрерывные столкновения, бонусы, независимость от частоты кадров, задержки, недоступное хранилище и ошибки статической сборки. Проходимость проверяется симуляцией 1 000 последовательностей по 16 секунд на четырёх уровнях сложности, а также длинными забегами до максимальной скорости. Бот реагирует за 0,3 секунды до преграды и использует реальные переходы и столкновения. Браузерные сценарии проходят все учебные оценки точности, комбо и Overdrive на экране 320 × 568, проверяют настройки, управление, паузу, сохранение рекорда, узкие экраны, изменение высоты окна и поворот. Эмуляция не заменяет настоящий Android.

Для архивирования нужны системные утилиты `zip` и `unzip`; они доступны в используемом окружении и на GitHub runner `ubuntu-latest`. Скрипты используют встроенную поддержку TypeScript в Node.js 24 и не добавляют библиотек для упаковки.

## Устройство проекта

- `src/game/model.ts` — правила игры, фиксированный шаг 120 Гц и генерация трассы без зависимости от Phaser.
- `src/game/config.ts`, `geometry.ts`, `reachability.ts`, `random.ts` — параметры, геометрия, проверка достижимости и воспроизводимые случайные последовательности.
- `src/game/timing.ts`, `progression.ts`, `events.ts` — проверяемые попытки точного переключения, накопительные бонусы, комбо и Overdrive.
- `src/game/patterns.ts`, `tutorial.ts` — серии препятствий и отдельный учебный режим.
- `src/audio.ts` — один Web Audio контекст, процедурные сигналы и не более шести голосов.
- `src/game/scene.ts` — неоновые фигуры и трасса, нарисованные средствами Phaser; внешние изображения и шрифты не нужны.
- `src/game/storage.ts` — чтение и сохранение рекорда с обработкой ошибок браузера.
- `src/ui.ts` и `src/style.css` — адаптивный интерфейс, доступные HTML-кнопки, русский и английский тексты.
- `src/main.ts` — связь модели, интерфейса, ввода и автоматической паузы.
- `scripts/` — проверка статической сборки и ZIP.
- `.github/workflows/` — CI, Pages и отдельный ручной запуск подготовки ZIP.

Стандартные препятствия доступны сразу, чередующиеся серии — после 12 секунд, ритмичные цепочки из 3–5 преград — после 28. Между сериями есть восстановление. Генератор подтверждает целую последовательность с учётом текущей координаты и незавершённого перехода игрока. При неудаче он проверяет зеркальный вариант или откладывает появление, не меняя старые преграды. Подробности — в [GAME_DESIGN.md](GAME_DESIGN.md).

## GitHub Pages и проверка с Android

После проверки и ручного коммита исходников:

1. Отправьте изменения в feature branch и создайте PR самостоятельно. Дождитесь зелёного `CI`.
2. Предыдущее падение `actions/configure-pages@v5` связано с неактивированным Pages. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**. Это [официальный способ настройки](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).
3. После ручного merge в `main` сначала выполняется `CI`, затем `GitHub Pages preview` публикует ровно артефакт успешно проверенного запуска. Ничего не собирается из непроверенной ветки в job публикации.
4. Откройте ссылку из environment `github-pages`. Для текущего репозитория ожидаемый адрес — `https://ilyanius31.github.io/endless-rush/`; он становится доступен только после успешного deployment.
5. На Android откройте этот адрес в Chrome или Яндекс Браузере. Начните забег, переключите полосу, проверьте паузу, сворачивание браузера, поворот и перезапуск. После проигрыша обновите страницу и проверьте рекорд.

На телефоне не нужны Node.js, APK или аккаунт Yandex Games. CI работает на PR и push в `main`; его можно также вручную запустить на `main` через **Actions → CI → Run workflow**. Pages использует `configure-pages`, `upload-pages-artifact` и `deploy-pages` с отдельным job и ограниченными правами, согласно [документации GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

Vite автоматически использует `/<repository>/` при наличии `GITHUB_REPOSITORY`; для репозитория вида `<owner>.github.io` используется `/`. Локально по умолчанию — `./`. Пользовательский домен или другой путь задаётся через `PAGES_BASE_PATH` при сборке и запуске preview. Для локальной проверки подкаталога:

```bash
PAGES_BASE_PATH=/endless-rush/ npm run build:preview
PAGES_BASE_PATH=/endless-rush/ npm run test:browser -- --config playwright.preview.config.ts
```

Проверки PR подготавливают скачиваемый preview, но не публикуют новую live-страницу для каждой feature branch. Постоянный Pages preview обновляется только из `main`.

## Yandex ZIP и артефакты

В успешном запуске **Actions → CI** откройте **Artifacts → neon-rush-yandex**. Скачайте и распакуйте контейнер GitHub artifact: внутри находится готовый `neon-rush-yandex.zip`; именно этот внутренний ZIP предназначен для будущей загрузки в консоль. Артефакты сохраняются 14 дней. Альтернативный ручной запуск: **Actions → Yandex ZIP foundation → Run workflow**.

`standalone-preview` содержит проверенную статическую Pages-сборку. `browser-results` содержит снимки экрана и трассировки ошибок браузерных тестов. Наличие этих файлов в рабочем дереве не означает, что Actions уже запускался или артефакты загружены на GitHub.

Yandex-сборка использует относительные ресурсы, `index.html` в корне, имена ASCII без пробелов и проверку размера меньше 100 МБ. `build-info.json` явно указывает `sdkIntegrated: false`. Это сохранённая основа упаковки с механиками этапа 2, а не готовый к модерации релиз: SDK, облачные данные, платформенные события и реклама ещё не подключены. Для локального запуска и Pages они не нужны. План публикации — в [YANDEX_RELEASE.md](YANDEX_RELEASE.md).

## Ограничения и дальнейшая работа

Магазин, задания, рейтинги, постоянная валюта, облачные сохранения и монетизация не реализованы; см. [ROADMAP.md](ROADMAP.md). Баланс новых окон и ритмов требует отзывов игроков. Язык по умолчанию русский, английский выбирается вручную; автоматический выбор языка планируется позже.

Canvas ограничен логическим буфером `420 × 760`, независимо от DPR устройства, и масштабируется через Phaser FIT. Это ограничивает нагрузку, но на плотных экранах графика может быть менее резкой. Частота рендера ограничена 60 FPS; слабое устройство может работать медленнее. В низком альбомном окне меню использует компактную вёрстку. Реальный Android, Safari и фактические 60 FPS на телефоне нужно проверить отдельно.

Рекорд хранится только локально, не защищён от ручного изменения и не синхронизируется между устройствами. Смена домена или порта создаёт отдельное хранилище. Без доступного `localStorage` рекорд живёт только в памяти страницы.

Перед коммитом проверьте управление и сложность, выполните проверки и просмотрите `git diff` вместе с новыми файлами. Описание для ревью подготовлено в [docs/PR_DESCRIPTION.md](docs/PR_DESCRIPTION.md). `dist/`, `artifacts/`, зависимости, кеши и результаты проверок исключены из Git.
